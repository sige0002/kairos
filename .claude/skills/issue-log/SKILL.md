# issue-log

作業中にぶつかった問題と、その解決方法を**簡潔に**残すためのスキル。
`issue/issue_1.md` という1つのファイルに、問題ごとのエントリを**追記して蓄積**する。

## 保存場所

- `issue/issue_1.md` — ここに全エントリを追記していく（`issue/` 直下に置く。下層フォルダは作らない）。
- 200行を超えたら `issue/issue_2.md` を新規作成し、以降はそこに追記する（`issue_3.md` …と続ける）。
- `issue/` は `.gitignore` 対象。コミットされないローカル知識ベースなので、ファイルが無ければ作ってよい。

## 書式（厳守：簡潔に）

ファイル先頭に `# Issue log (issue_N)` の見出しを1つ。各問題は `##` エントリで追記する:

```markdown
## <問題の短いタイトル> (YYYY-MM-DD)

**問題**: <2行以内で、何が起きたか>

**解決**: <5行以内で、どうしたら直ったか>

area: <下の area から1つ以上（カンマ区切り）>
kind: <下の kind からちょうど1つ>
```

- **問題は2行以内、解決は5行以内**。原因と対処の要点だけ。
- **タイトルに固有名を入れる**（エラーメッセージ・関数名・仕組み名 = `uplot` `arming` `video_check` 等）。
  これらは**タグにしない** — タイトル/本文を `grep` すれば当たるので、タグを無限に増やさない。
- 日付は今日の日付。新しいエントリは**ファイル末尾に追記**する。

### タグは統制語彙から選ぶ（自由記述しない）

`grep` によるタグ検索を確実にするため、タグは下の**固定リストのみ**を使う（表記ゆれ禁止：`rosbag2` などではなく実サービス名で）。

**area:（1つ以上）— どこの話か**

| タグ | 対応 |
|---|---|
| `recorder` | rosbag2_recorder |
| `monitor` | topic_monitor |
| `streamer` | webrtc_streamer |
| `probe` | topic_probe |
| `orchestrator` | api_orchestrator |
| `dora` | dora_runner |
| `frontend` | frontend |
| `infra` | Makefile / compose / Dockerfile / .env（ビルド・運用基盤） |
| `repo` | git運用 / worktree / 命名 / docs（リポジトリ横断） |

**kind:（ちょうど1つ）— どんな種類か**

`bug`（不具合） / `perf`（速度・リソース・トークン） / `build`（ビルド・依存・環境構築） /
`config`（設定・env・挙動） / `test`（smoke・pytest・検証） / `git`（git運用） /
`experiment`（計測・切り分けの知見） / `docs`（ドキュメント・命名規約）

新しい area/kind が欲しくなったら、まず既存で表せないか確認する。安易に増やさない（増やすときはこの表も更新）。

## 手順

### 作業開始前（重複チェック — 全文Readしない）

1. まず**見出し + タグだけ**を grep して検索面を作る（本文はコンテキストに載せない）:
   `grep -nE '^## |^area:|^kind:' issue/issue_*.md`
   キーワードが具体的なら直接絞る: `grep -inE '<keyword>' issue/issue_*.md`
   area で絞る: `grep -n '^area:.*recorder' issue/issue_*.md` ／ kind で絞る: `grep -n '^kind: perf' issue/issue_*.md`
2. 候補が出たら、その**行番号周辺だけ** Read する（`offset`/`limit` 指定）。**全文 Read はしない。**
3. 既に同じ問題があれば、新規追記せず**その既存エントリを更新する前提**で進める。

### 作業終了時（記録）

1. 今回の問題と解決を上記の書式でまとめる（area/kind を付ける）。
2. **既存に該当エントリがあれば**: そのエントリを修正する（解決方法が変わった／補足が増えたら更新）。
3. **なければ**: 一番新しいファイルの末尾に `##` エントリを追記する。
4. 追記後、そのファイルが**200行を超えていたら** `issue_(N+1).md` を新規作成し、先頭見出しを置く。
5. 書式どおり**問題2行・解決5行以内**、タグは統制語彙のみ。冗長なら削る。

## 原則

- 記録は**簡潔さが命**。コードブロックやコマンドは1〜2行の要点のみ。
- 1エントリ=1問題。複数の問題を1エントリに混ぜない。
- **タグは area/kind の固定リストから**。固有名はタイトルへ（タグを無限に増やさない）。
- 解決していない問題は「解決」に暫定対処と未解決である旨を1行で書く。
- 本文・タイトルは日本語でよい（このプロジェクトのドキュメント方針に合わせる）。
