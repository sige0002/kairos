# Evidence Matrix — 指示ファイル有効性の実証研究

verified_date: **2026-07-31**。効果を主張する前にここを読む。
**結論の要約: 「AGENTS.md があるほどよい」も「無い方がよい」も一般には言えない。
内容の質（人間が書いたか・無関係な記述が無いか）が支配的要因。対象リポジトリで A/B 測定する。**

注意: 以下は1件（PROFES 2025）を除きすべて**未査読プレプリント**。数値を引用するときは実験条件とセットで。

## 主要研究

### Gloaguen et al. (ETH Zurich), "Evaluating AGENTS.md" — arXiv:2602.11988（2026-02、改訂 2026-06）

- 条件: SWE-bench 系 + 実リポジトリ issue。Claude Code / Aider / OpenHands / SWE-agent、Claude Sonnet 4.5 / GPT-5 系ほか
- 結果: **LLM 生成の指示ファイルは成功率を平均約 −3%、推論コストを +20% 超**（GPT-5.2 +22%）。
  **開発者が書いたファイルは平均約 +4% 成功率向上**（コストは最大 +19%）。
  汎用的な「リポジトリ概要」記述は無益で、除去すると平均 +2.7% 改善
- 含意: 「指示ファイル＝有害」は誤読。**自動生成した概要文を置くくらいなら置かない方がよい**。
  このスキルが生成時に「マニフェスト・CI から検証した事実だけを書く」のはこの結果に基づく

### Lulla et al., "Impact of AGENTS.md on Efficiency" — arXiv:2601.20404（ICSE JAWs 2026 ワークショップ）

- 条件: 10リポジトリ × 124 PR のペア実験（同一タスクをあり/なしで）。Codex / Claude Code
- 結果: **実行時間中央値 −28.64%、出力トークン −16.58%**（中央値 2,925→2,440）。タスク完了行動は同等
- 限界: 小規模・ワークショップ論文。**「効率」の主張であり「成功率向上」ではない**（Gloaguen と測定軸が違うため両立しうる）

### dos Santos et al. (UFMG), "Configuration Smells in AGENTS.md" — arXiv:2606.15828（2026-06）

- 条件: GitHub スター上位 100 リポジトリ（AGENTS.md 39 + CLAUDE.md 61）。LLM 検出＋手動検証
- 結果: **Lint Leakage 62/100、Context Bloat 42/100（200行閾値）、Skill Leakage 35/100**、
  Conflicting Instructions 28%、Init Fossilization 24%、Blind References 16%。91/100 が最低1 smell
- 限界: **存在率の記述調査であり、smell が成功率を悪化させるという介入実験ではない**。
  チェックリスト語彙（scripts/audit_guidance.py の検出分類）としてのみ使う。200行閾値も慣習値

### McMillan, "Instruction Adherence … Factorial Study" — arXiv:2605.10039（2026-05、単著）

- 条件: file size / 指示位置 / ファイル構成 / 矛盾、の4要因実験。1,650 セッション、TypeScript 2 コードベースのみ
- 結果: **4変数とも有意差なし（file size は「効果なしのエビデンス」、Bayes factor 0.05–0.10）**。
  唯一の強い効果は「セッション内で生成関数が増えるほど遵守率が 1 ステップあたり −5.6%」
- 含意: **「短いほどよい」への直接反証候補**。ただし単著・2コードベースで一般化は限定的。
  「短くしろ」ではなく「無駄を書くな」（Gloaguen）が実証的に支持される主張

### 長文脈研究（間接証拠）

- **Lost in the Middle**（Liu et al., NAACL 2024、**査読済み**）: 文脈中央の情報で精度 30% 超劣化の U 字
- **Context Rot**（Chroma, 2025-07、企業技術報告・非査読）: 18 モデルでトークン長増加に伴う劣化
- 注意: これらが劣化を確認したのは数万トークン級。**AGENTS.md の典型スケール（数百〜数千トークン）への外挿は未実証**

### 記述研究

- Chatlatanagulchai et al., "Agent READMEs" — arXiv:2511.12884: 2,303 ファイルの大規模調査。
  Testing 75% / Architecture 68% は手厚いが Security 14.5% / Performance 14.5% は薄い
- 同著者ら PROFES 2025 — arXiv:2509.14744（**今回唯一の査読済み**）: 253 CLAUDE.md の構造分析
- METR (2026-03): SWE-bench 自動採点をパスした PR の実マージ率はスコアより約 24pt 低い →
  **ベンチマーク成功率だけでなく時間・トークン・人間レビュー通過も測る**

## 自リポジトリでの評価設計（先行研究の作法）

1. **ペア実験**: 同一タスク集合を指示ファイルあり/なし（または旧版/新版）で実行し差分を見る
2. **試行数**: タスクあたり最低3 run（可能なら5+）。1試行で結論しない
3. **統計**: ペア設計なら Wilcoxon 符号順位検定、信頼区間はブートストラップ。
   効果が無いことを主張したいなら Bayes factor
4. **測定値**: 成功率だけでなく実行時間・出力トークン・人間の修正回数。
   自動採点と人間の採用判断は乖離する（METR −24pt）
5. 実装は evals/evals.json + Claude Code は skill-creator の Eval/Benchmark モード、
   Codex は `codex exec --json --output-schema` を使う
