# マルチエージェント協調

独立に進められる具体的な仕事だけを委任する。並列化の体数や役割を固定せず、
実装、調査、レビューのどこに独立作業の価値があるかで選ぶ。
逐次処理で足りる仕事にチーム編成を追加しない。

## 委任の契約

各担当へ、目的、必要な入力、期待する成果物、所有パス、検証方法、認可された
副作用の範囲を渡す。親が行う判断と、担当が自律的に完了してよい範囲を明確にする。
子は新しい権限が必要な操作や重要な未確定事項を親へ返す。

共有ファイル・依存 manifest・設定の変更は所有者を決める。
同一ファイルへの並列編集が避けられなければ、順番を調整するか worktree で分ける。
依存関係のある仕事は前段の成果物を受けて開始し、統合後に影響する正準ゲートを使う。
フェーズごとの無関係な全テストや未導入の型チェックを追加しない。

利用可能な協調ツールを使い、環境固有の名前を決め打ちしない。報告には変更パス、
検証結果、未解決事項、レビューしたコミットや成果物の版を含める。
独立レビューでは依頼と原資料を渡し、欲しい結論を先に教えない。

## 長時間ジョブと共有資源

長時間の学習・評価などを任せる場合だけ、プロセス/セッション ID、ログパス、
完了・停滞・異常の判定条件と次の認可済み工程を指定する。
親は報告とログ/成果物で進行を確認する。プロセス名検索だけでは、別担当の検索
コマンド自体を誤検出することがある。

常駐 Monitor や無限ループは既定にしない。ジョブの所要時間に合う確認間隔と
期限を選び、失敗の理由を調べてから再試行する。同じ失敗を新しい担当で反復せず、
引継ぎが必要なら旧担当の実行状態を確かめる。

GPU や実機など競合する資源の実行所有者は一人にする。引継ぎ時は旧担当へ新規起動を
止めるよう伝え、稼働ジョブを確認してから移譲する。認可された工程だけを継続し、
終了時は自分たちが起動した資源だけを片付ける。
